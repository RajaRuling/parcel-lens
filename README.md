# Parcel Lens

Can a small model look at a picture of one parcel and say whether it needs a second look for damage? This repository is a worked, reproducible test of that idea. The claims were written down before any model was trained, every result is kept (including the failures), and a static website in `docs/` shows it all.

**Everything here is synthetic.** The parcel pictures are drawn by the included generator (`src/procedural.py`); no real photograph was tested, so nothing here says how a model would do on real parcels.

## Results

On 4,800 generated scenes a small trained model separates damaged from clean parcels well on pictures in its own style (ROC AUC 0.95) but fails the review target (it misses too much damage for the false alarms allowed) and drops to AUC 0.64 on an unseen picture style. Production auto-clear is disabled. Full numbers with confidence intervals: [REPORT.md](REPORT.md).

### Experimental: the Jev image model

I also tried a general image model I did not train, Jev (model jev-1.14.0), on 150 of the synthetic parcel images. Its maker, TypeSafe, marks image input and Box (a rectangle drawn around the target) as experimental. One fixed prompt, one run, nothing tuned.

| Test | My trained model | Jev |
| --- | --- | --- |
| Damage yes/no, score out of 100 (AUC) | 96 | 76 |
| Damaged parcels caught (recall) | 92% | about 1 in 6 (17%), with no false alarms |
| Box: boxes overlapping the true damage by at least half | cannot draw boxes | 59% |
| Box: typical (median) overlap with the true damage | not available | 54%, against 7% for a fixed box in the middle of the picture |
| Clean parcels given a box anyway | not applicable | 75 of 75 |
| Speed per picture | not measured here | about 0.15 s |
| Cost per picture | none | about 698 input tokens |

The 54% and the 7% are the same measure and can be compared; 59% is a different measure (a share of boxes) and must not be compared with 7%. Because the Box step always answers, a presence check has to come first.

**Verdict:** Jev's Box is promising for locating damage; it is not yet a replacement for a model trained on your own pictures.

Limits: a single run; the API refused the small original images, so every picture was sent enlarged 2x; I did not check whether Jev gives the same answer when asked again; synthetic parcels only. Measured numbers are in `docs/jev/parcels.json`. The scripts, the saved answers and the pre-registered claims are in [`jev/`](jev/); real runs need your own key in the environment variable `JEV_API_KEY` and cost real calls (see `jev/README.md`).

Screenshots of the site at 390 px and 1280 px (including the Jev section: `jev-390.png`, `jev-1280.png`) are in `docs/screenshots/`.

## Run it

The site is plain HTML, CSS and JavaScript with no build step: open `docs/index.html` in a browser, or serve `/docs` with GitHub Pages.

To rebuild the results and run the tests (Python 3.14 was used; any recent 3.x should be close):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pytest          # offline checks
(cd jev && ../.venv/bin/python -m pytest tests)   # Jev scripts, stub transport, no network
make results                        # regenerates the 4,800 images (about 250 MB, not in the repository) and every number
```

The generated images are not stored in this repository; `make results` recreates them from fixed seeds. The trained model files are small (under 1 MB) and are included.

## Limits

No real photographs; same-generator tests can reward rendering shortcuts; one parcel and one yes/no label per image; no field trial. More in [NOTES.md](NOTES.md) and on the site.

## Data

The parcel images and their damage boxes are original synthetic work generated by `src/procedural.py` (CC0 1.0, see `data/LICENSE.txt`). The repository contains no real photographs and no third-party images.
